# Доделать расширение dn1sup_export_3d + тесты

## Текущее состояние (что нашёл)

Реализованы Phase 1–3 и часть Phase 6 (регистрация, меню, экспорт GLB из одного merged-mesh, вьюер Three.js, vendor-модули). **Найдено 2 критических бага и ряд пробелов:**

1. **Координаты перевёрнуты**: `coordinate.rb:8` маппит `(x, y, z) → (x, -z, -y)` — ось Z (вверх) уходит в -Y glTF, детерминант −1. Модель «висит» ниже нуля (в `test_model.glb` Y = −0.319..0). Правильная мапа: `(x, z, -y)` (det +1, вращение −90° вокруг X) + масштаб 0.0254.
2. **Off-by-one в узлах glTF**: `glb_exporter.rb:48,58` — после `[root] + @flat_nodes` все дочерние индексы сдвинуты; корень ссылается сам на себя (невалидный glTF, риск бесконечной рекурсии в загрузчиках).
3. **Выделение объектов мёртво сквозь весь конвейер**: все грани сливаются в один меш; `extras.sketchup` пишется на пустые узлы без мешей, а вьюер читает `userData` только с мешей → клик/подсветка/метаданные не работают.
4. **Нет текстур и UV** (Phase 4), **нет моста HtmlDialog** (Phase 8 — ни одного `add_action_callback`/`execute_script`), `index bufferView` имеет target 34962 вместо 34963, диалог не удерживается в переменной (GC может закрыть окно), `check_glb.rb` ссылается на чужой путь, нет ни одного теста, нет README/LICENSE/RBZ-упаковки, ни одного коммита в git.

## План работ

### A. Экспортёр: корректность и архитектура (баги 1–3)
- `coordinate.rb`: мапа `(x,z,-y)·INCH_TO_METER`; добавить `matrix4(t)` — конверсия `Geom::Transformation` в glTF 4×4 (column-major, метры) как C·M·C⁻¹, где C — матрица смены базиса. Точный layout `Transformation.to_a` сверить по докам/живым тестом с известным поворотом.
- Переписать `geometry.rb` + `glb_exporter.rb` на **иерархию узлов вместо merged-mesh**: геометрия каждого контейнера (группа / определение компонента / модель) — в локальных координатах контейнера, трансформации — на узлах glTF (`matrix`). Определения компонентов кэшируются по `persistent_id` и их дерево узлов клонируется на каждый инстанс (меши переиспользуются — без дублирования геометрии; это же чинит выделение). Зеркальные инстансы — матрица с det<0 (по спецификации glTF загрузчики сами переключают winding; проверить визуально).
- Фиксы: target 34963 для индексов; min/max без `each_slice(3).to_a`; дыры граней — оставить предупреждение + заливку контуром (задокументированный fallback, свой триангулятор не пишем по AGENTS §9); нормали с учётом только поворота+зеркала (без неравномерного масштаба — задокументировать).

### B. Материалы и текстуры (Phase 4)
- `materials.rb`: `baseColorFactor` = цвет-тинт SketchUp, `baseColorTexture` через `images/textures/samplers` с внедрением PNG/JPEG в BIN-чанк (bufferView без target, mimeType по расширению); неподдерживаемые форматы (psd/tif) — предупреждение и fallback на цвет. `alphaMode: BLEND` по альфе материала; `doubleSided: true` (fallback вместо back_material — задокументировать). Sampler wrap REPEAT (по умолчанию spec).
- UV: `face.get_UVHelper().get_front_UVQ(point)` → `TEXCOORD_0` (u/q, v/q); направление V (flip 1−v) проверить текстурированным тестом.

### C. Вьюер (Phase 6–7)
- `viewer.js`: propagate `extras` с узлов-предков на меши при загрузке → работает выбор по `persistent_id`; снять выделение по пустому клику; `setPixelRatio`; публичный API по AGENTS §22 (`loadModel/selectObject/focusObject/getObject/clearSelection/on`), события `viewerReady`/`objectSelected` сохранить; убрать мёртвый код. `index.html` — без CDN (как есть).

### D. Мост HtmlDialog (Phase 8)
- `main.rb`: диалог удерживается в переменной модуля; `add_action_callback("viewer_ready")` (лог), `add_action_callback("object_selected")` — найти entity по `persistent_id` рекурсивным обходом и выставить `model.selection` (только чтение модели, без модификации). JS→Ruby через документированный `skp:` механизм. Никакого eval произвольного кода. Список команд моста — в README.

### E. Инфраструктура
- `logger.rb` (info/warn/error + debug-флаг, AGENTS §28); `version.rb` — единственный источник версии (AGENTS §36).
- `main.rb`: пункт меню «Export selected objects» (scope `:selection`), убрать мёртвый `file_url`, сообщение об ошибке с контекстом (AGENTS §27).
- `build/check_glb.rb` — путь через `__dir__`.
- `README.md` (архитектура, координатная мапа, мост, fallback'и, API вьюера), `LICENSE` (MIT), уведомление о Three.js (MIT) в `vendor/three/`.
- `build/package.rb` — сборка `.rbz` (Compress-Archive, без новых гемов): только `src/` + `dn1sup_export_3d/`, без `test/`/`build/` (AGENTS §35).

### F. Тесты (явный запрос) — `dn1sup_export_3d/test/`, запуск внутри SketchUp
- `test_helper.rb`: мини-харнесс (assert_*, счётчик, отчёт) + чисто-Ruby GLB-парсер (заголовок, чанки, accessors, декодирование) + билдеры сцен (куб, компоненты, материалы) на `model.start_operation`/`abort_operation` — тесты не портят модель.
- `glb_structure_test.rb`: контейнер/чанки/выравнивание; accessor min/max соответствует данным; индексы узлов валидны (нет ссылок на себя, все в диапазоне).
- `geometry_test.rb`: куб (bbox 1м³, вверх = +Y, 12 треугольников, CCW-обмотка), вложенные группы (иерархия+матрицы), повёрнутый компонент (roundtrip 90°), зеркальный инстанс (det<0, мировой bbox), вогнутая грань, несколько материалов, экспорт выделения.
- `materials_test.rb`: solid color, альфа→BLEND, текстура внедрена (mimeType, TEXCOORD_0, V-flip, связь texture→material).
- `structure_test.rb`: определение + 2 инстанса шарят один mesh-индекс; у инстансов свои `persistent_id` в extras.
- `export_test.rb`: пустая модель (валидный минимальный GLB), путь с пробелами и юникодом, smoke на ~100 граней (< 5 c).
- Прогон: через `console_eval`/`ext_test` в живом SketchUp (MCP уже подключён), итерации до зелёного; плюс браузерный smoke-тест web-пакета (Three.js грузит GLB, клик выделяет) через browser-use.
- Git: маленькие осмысленные коммиты `fix:`/`feat:`/`test:` по ходу (репозиторий пуст).
